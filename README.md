> A hands-on workshop kit for building a **real-time 3D geospatial intelligence platform** — by
> directing an AI coding agent instead of typing the code yourself.

You bring a coding agent (Claude Code, Codex, or similar). This repository brings the
**prompts, specs, plans, and skills** that steer it — step by step — from an empty folder to a
live command-center globe streaming public OSINT feeds, with cinematic post-processing filters.

It's a practical lesson in **"vibe coding" done as real engineering**: spec-driven development,
disciplined prompting, review gates, and AI-assisted debugging.

---

## What you'll build

A simplified, self-hostable clone of a browser-based intelligence dashboard:

- **A 3D globe** (CesiumJS) over a dark tactical basemap, filling the screen.
- **Live OSINT layers** — commercial & military flights, ships, satellites & the ISS, earthquakes,
  radiation, and critical infrastructure — streamed in real time.
- **Cinematic post-processing filters** — CRT, Night Vision, FLIR.
- **A declarative source engine** — add a data feed by writing one YAML file (HTTP transport;
  JSON / GeoJSON / XML / CSV).

**Stack (built during the workshop):**

| Layer | Tech |
| :-- | :-- |
| Frontend | Vite · React 18 · Redux Toolkit + RTK Query · MUI · TypeScript · **CesiumJS** · WebSocket |
| Backend | Node.js · Express · TypeScript · **SQLite** (`better-sqlite3`) · WebSocket · OpenAPI 3.0 |
| Tooling | Makefile · monorepo (NPM workspaces) |

The platform is **generated by you and your agent** — it is not checked into this repo. This repo
is the *kit* that gets you there.

---

## Who this is for

Security researchers, OSINT practitioners, and engineers who want to learn AI-assisted development
by building something real. Comfortable with a terminal and Git; **no prior AI-agent experience
required.**

The materials are **model-agnostic** — the prompts are plain Markdown with no proprietary syntax,
so they work well with Claude Sonnet 4.5, GPT-4o-class models, and similar (including cheaper or
self-hosted models).

## How the workshop works

The methodology is **spec-driven development** powered by the [Superpowers](https://github.com/obra/superpowers)
skill set. Nothing gets coded until the design is written down and reviewed:

```
  PROMPT  ─▶  SPEC  ─▶  PLAN  ─▶  SUBAGENT-DRIVEN BUILD
             (review)   (review)
```

You catch design mistakes in the spec (minutes) instead of in the code (hours). The build is
broken into **6 self-contained steps**, each producing a working piece you can see and test.

### Two paths

- **Path A — full spec-driven (recommended for learning):**
  Run `docs/PROMPT_N_*.md` in your agent → it generates a spec and a plan → **you review both** →
  it executes the plan with subagents.

- **Path B — token-saver (for limited accounts):**
  Skip generation and point your agent straight at the provided plan, e.g.
  *"Use a subagent-driven approach to execute `example-docs/superpowers/plans/01-project-setup-plan.md`."*
  Review the result, then continue with plans 2–6.

Either way: **validate at every milestone.** After each step, open `http://localhost:3000`,
exercise what was built, and tell the agent to *fix the bugs* or *continue to the next step*.

### The 6 build steps

| # | Step | Produces |
| :-- | :-- | :-- |
| 1 | Project setup & monorepo foundation | Makefile, backend (Express + SQLite + OpenAPI), Vite/React/MUI frontend with a **simple Cesium globe** |
| 2 | Declarative ingestion engine | YAML source loader, HTTP fetcher, JSON/GeoJSON/XML/CSV parsers, field mapper, scheduler |
| 3 | Backend WebSocket API | Real-time telemetry push + command channel |
| 4 | Frontend globe dashboard | Live markers, layer controls, entity inspector, telemetry HUD |
| 5 | Cinematic filters & polish | CRT · Night Vision · FLIR overlays |
| 6 | Integration & debug | End-to-end wiring, visual verification, bug fixes |

## Getting started

1. **Clone this repo** and open it in your coding agent of choice.
2. **Install the recommended tooling** (below) — at minimum Superpowers, RTK, and Chrome DevTools MCP.
3. **Run step 1** (Path A or B). Review the generated spec & plan, then let the agent build.
4. **Watch it come alive** at `http://localhost:3000` (`make dev`).
5. **Repeat** for steps 2 → 6, validating each milestone.
6. **Extend it** — add your own data feeds with the `onboard-source` skill.

## Data sources

Sources are **declarative** — each is a single YAML file describing how to fetch and map a public
feed onto the globe. No engine changes needed to add one.

- **Add any feed with the skill:** `skills/onboard-source/SKILL.md` takes a **URL**, inspects the
  response, and writes a valid source definition for you.
- **Start from an example:** `skills/onboard-source/examples/` ships **19 ready, validated,
  no-auth source definitions** across all five categories — flights, ships, satellites/ISS,
  earthquakes/volcanoes/wildfires, radiation/nuclear/power. Drop one in and go.

A source, demystified — it's just data you fetch over HTTP, parsed and pinned to a point:

```yaml
name: usgs_earthquakes
transport: { type: http_poll, url: "https://earthquake.usgs.gov/.../all_hour.geojson", interval: "60s" }
parser:    { format: geojson, records_path: "features" }
entity:      { external_id: "id", name: "properties.place", category: "geological" }
observation: { latitude: "geometry.coordinates[1]", longitude: "geometry.coordinates[0]", timestamp: "properties.time" }
recording:   { mode: upsert }
```

## Prompt-writing principles

The prompts here follow a **universal, model-agnostic template** (plain Markdown, strict top-to-bottom
order) so they behave consistently across models:

1. **Persona** — who the model should be.
2. **Core Task** — the single directive.
3. **Constraints** — the rules, as a bulleted list.
4. **Format Requirements** — exactly what the output should look like.
5. **Analysis Steps** *(optional)* — think before answering.
6. **Input Data** — the variable data, fenced at the very bottom.

Headers chunk attention, lists parse better than prose, bold marks hard rules, and positive
framing ("do X") beats negatives ("don't do Y").
